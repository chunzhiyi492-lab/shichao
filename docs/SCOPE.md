# 拾潮 · 功能范围（SCOPE）

> 阶段 2 产物。只做第一批，后两批等用户确认后再做。
> 一切以 `docs/PRINCIPLES.md` 为准，任何功能不得违反七条合规底线。

## 地基（所有功能都依赖它）

- 本地数据层：IndexedDB（Dexie），数据层与界面层分开。
- 设计规范：颜色、字体、间距（阶段 3 定，阶段 5.1 落地）。
- 导航：手机端底部导航（阶段 3 定）。

没有地基，任何一批都做不了。地基在阶段 5.1 先做。

## 第一批（核心，先做）

| 功能 | 内容 | 依赖 |
| --- | --- | --- |
| 贝壳盒 | 灵感速记：快速记录文字，可加标签、心情、日期，可搜索筛选 | 地基 |
| 设定卡 | 人物卡、关系卡、世界观卡，字段可自定义；关系用可拖动节点展示 | 地基 |
| 伏笔 | 每条有标题、说明、关联设定卡、状态（已埋下 / 已回收 / 已放弃） | 设定卡（关联设定卡）；地基 |
| 潮位首页 | 抽象海岸线，水位缓慢起伏；未回收伏笔是水下礁石（模糊轮廓 + 标题，点开看详情）；标为“已回收”时水位轻轻下降、礁石逐渐露出；首页只写一句话“水下还有 N 块礁石” | 伏笔（状态）；地基 |

依赖链：地基 → 贝壳盒、设定卡 → 伏笔 → 潮位首页。

说明：
- 贝壳盒和设定卡互不依赖，可以并行做（阶段 5.2 先做它俩）。
- 伏笔必须等设定卡有了才能关联，潮位首页必须等伏笔状态有了才能算水位和礁石。
- 第一批不含任何 AI 调用，不需要 Key，不需要设置页。

## 第二批（AI，后做）

| 功能 | 内容 | 依赖 |
| --- | --- | --- |
| 一致性检查 | 用户粘贴自己的草稿并选择相关设定卡，AI 指出前后矛盾处 | 设定卡；设置页（Key）；AI 调用确认流程；地基 |
| 提问式灵感激发 | AI 根据选中的笔记提出 5 个开放式问题 | 贝壳盒（选中的笔记）；设置页（Key）；AI 调用确认流程；地基 |

依赖链：第一批（设定卡、贝壳盒）+ 设置页（Key）+ 确认流程 → 第二批。

说明：
- 两段 AI 提示词固定写在代码里，见阶段 5 的提示词规范；一致性检查结果页顶部固定显示「以上仅为提示，请你自行判断。」
- 每次调用前弹出确认「将把你选中的这段文字发送给 AI 服务，是否继续？」，并要求勾选「这是我自己的原创文字」，未勾选不得发送（PRINCIPLES 第 5 条）。
- 没有 Key 时两个功能都不可用，界面要明说去设置页填 Key，而不是静默失败。

## 两个需要用户确认的点（阶段 2 发现的）

### 1. 设置页要提前，不能等到第三批

- 设置页在你的分批里列在第三批，但第二批的 AI 功能没有 Key 就跑不起来。
- 建议：设置页分两次做——阶段 5.4 先做最小版（只含 AI Key 填写），让 AI 功能能用；阶段 5.5 再补全（数据清空、导出入口等）。这与你阶段 5 的顺序一致（5.4 已含设置页），只是把分批里的位置说清楚。
- 理由：不提前，AI 功能在 5.4 无法验收；不分两次，5.5 又要返工。

### 2. 潮汐表的每日字数，建议手动登记

- 你没说每日字数从哪来。建议：每天由用户自己填一个数字（当天写了多少字），有记录的天算创作天，连续天数按有记录的天算。
- 理由：贝壳盒记的是灵感碎片，草稿也不是整篇正文，自动从它们身上数字数会算错，还会把“记灵感”误算成“写正文”。手动填一个数最简单，也最诚实。
- 不扩范围：不做自动统计、不读草稿字数、不做目标提醒。

## 不做清单（明确划掉，避免以后扩大）

- 不抓取、不爬取任何网站；不批量导入他人作品。
- 不存他人作品原文、截图、译文；不设图片上传。
- AI 不模仿指定作者文风，不续写、复刻、改写他人作品，不用用户数据训练或微调。
- 不设账号、不设同步、不设服务器；不接统计、埋点。
- 不给每个区块加淡入上滑，不给每张卡片加悬停动画（设计克制，阶段 3 定）。
